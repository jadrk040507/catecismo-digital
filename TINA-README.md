# TinaCMS Integration — Catecismo Digital

## Overview

This integration adds TinaCMS visual content editing to the Catecismo Digital project, enabling non-technical content editors to update lessons, workbooks, and catechist guides through a visual interface with automatic GitHub commits.

## Architecture

```
repo/
├── tina/
│   └── config.ts           ← TinaCMS schema (24 collections + settings)
├── content/
│   ├── es/
│   │   ├── credo/          ← Lessons, workbooks, guides (ES)
│   │   ├── sacramentos/
│   │   ├── moral/
│   │   └── oracion/
│   ├── en/                 ← Same structure (EN)
│   └── settings/           ← Global site settings
├── src/
│   ├── pages/admin/        ← TinaCMS admin mount
│   └── content/            ← Astro content collections integration
├── .github/workflows/
│   ├── deploy.yml          ← Existing GH Pages deploy
│   └── tina-deploy.yml     ← Tina Cloud build + deploy
└── scripts/
    └── extract-tina-content.mjs  ← Extract lessons from .astro → markdown
```

## Content Structure

| Section    | Types                 | ES Path          | EN Path          |
|------------|-----------------------|------------------|------------------|

## Getting Started (Local Development)

```bash
# Set local mode
echo "TINA_PUBLIC_IS_LOCAL=true" > .env

# Start both TinaCMS and Astro dev servers
npm run dev
```

This starts:
- TinaCMS dev server (content API on port 4001)
- Astro dev server on port 4321
- TinaCMS admin available at `/catecismo-digital/admin/`

## Production Setup

### 1. Tina Cloud Account
1. Sign up at https://app.tina.io
2. Create a new project linked to this GitHub repository
3. Configure GitHub OAuth App:
   - Authorization callback URL: `https://content.tina.io/auth/{CLIENT_ID}/callback`
   - Homepage URL: `https://jadrk040507.github.io/catecismo-digital`

### 2. Environment Variables (GitHub Actions)
Add to your repository secrets:
- `TINA_CLIENT_ID` — From Tina Cloud project settings
- `TINA_TOKEN` — From Tina Cloud project settings  
- `TINA_SEARCH_TOKEN` — From Tina Cloud project settings

### 3. Deploy
Push to `main` — the GitHub Actions workflow will:
1. Build TinaCMS admin (`public/admin/index.html`)
2. Build Astro site
3. Deploy to GitHub Pages

## Visual Editor

Content editors access the visual editor at:

### What Editors Can Do
- **Edit existing content**: Click any text to edit inline with rich-text toolbar
- **Create new lessons**: Click "Add Document" in any collection
- **Delete content**: Remove outdated lessons
- **Upload media**: Images are stored in `public/uploads/`
- **Sidebar navigation**: Organized by section → content type

## Pedagogical Fields per Lesson

Each lesson has a `pedagogical` object with:

| Field | Description |
|-------|-------------|
| `bigQuestion` | Opening story/question (rich-text) |
| `content` | Main lesson content (rich-text) |
| `biblicalConnection` | Scripture integration (rich-text) |
| `reflection` | Reflection questions (rich-text) |
| `keyIdea` | One-line summary (textarea) |
| `culturalWealth` | Films, art, music (rich-text) |

## Migration from .astro to Content

The existing lessons are in `src/pages/es/credo/01-deseo-de-dios.astro` format.
New content should be authored in `content/` as markdown.

Run the extraction script to convert existing .astro lessons to markdown:
```bash
node scripts/extract-tina-content.mjs
```

## File Pattern Matching

TinaCMS uses file pattern matching to distinguish content types within the same directory:
- **Lessons**: Files NOT ending in `-workbook` or `-guide`
- **Workbooks**: Files ending in `-workbook`
- **Guides**: Files ending in `-guide`

## Schema Architecture

28 total collections:
- 24 section-content-type-lang collections (4×3×2)
- 1 settings collection (global)
- 3 auto-generated by TinaCMS (_graphql, _collections, _search)

The schema uses TinaCMS 3.x `defineConfig` with:
- `rich-text` for pedagogical content
- `string` with `textarea` UI for key ideas and verses
- `number` for ordering
- `object` for pedagogical structure grouping

## Integration Points

### Astro ↔ TinaCMS Bridge
The content bridge allows existing `.astro` pages to consume Tina-managed markdown:
```astro
---
// Example: reading from content/ instead of embedded HTML
import { readFileSync } from 'fs';
import { marked } from 'marked';
const content = readFileSync('content/es/credo/01-deseo-de-dios.md', 'utf8');
---
```

### GitHub OAuth
Tina Cloud handles authentication via GitHub OAuth. Editors authenticate with their GitHub account and get write access through Tina Cloud's git bridge.

### Automatic Commits
Every edit made through the TinaCMS visual editor creates an automatic commit to the configured branch, keeping the git history clean and traceable.
